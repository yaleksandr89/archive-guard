# Модель безопасности

Эта страница описывает границы проверок и извлечения архива. Она не является отчётом об аудите безопасности.

## Что считается недоверенным

Содержимое архива и его метаданные, включая имена и типы записей, размеры и расширения формата, считаются недоверенными. Приложение задаёт собственную политику ресурсов для конкретного сценария.

## Что проверяет `inspect()`

Проверяются нормализованные пути, совпадения и конфликты путей, типы записей, поддерживаемые возможности формата и лимиты ресурсов. Отклонение по политике возвращается в `InspectionResult::violations()`. Недоступный, нераспознанный или структурно повреждённый источник вызывает `ArchiveOpenException`.

## Граница контролируемого извлечения

`extract()` повторяет проверку архива по переданной политике; прежний `InspectionResult` не разрешает запись. Отклонение архива происходит до записи. Каталог назначения должен существовать, разрешаться в каталог, быть пустым и доступным для чтения; его конечный путь не может быть символической ссылкой. Необходимые подкаталоги создаются во время извлечения, а существующие цели не перезаписываются. Фактически записанные байты ограничиваются политикой и сверяются с принятыми размерами записей. Для TAR и TAR.GZ второй проход также сверяет извлекаемые записи с манифестом, принятым при первой проверке.

## Ограничения защиты ресурсов

Четыре обязательных лимита ограничивают исходный размер архива, число записей и размеры распакованных данных. Необязательный порог отношения сжатия — ограниченная эвристика: для ZIP она использует размеры из метаданных, для TAR.GZ — фактическое расширение потока декомпрессора; для обычного TAR она не применяется. Ни один порог не заменяет выбор лимитов под ресурсы приложения.

## Windows

При извлечении в Windows до записи дополнительно проверяются недопустимые и зарезервированные имена, завершающие точки и пробелы, а также коллизии путей, различающихся только ASCII-регистром. Поэтому `inspect()` может принять архив, который `extract()` в Windows отклонит с `ExtractionException`.

## Что не гарантируется

- Извлечение не атомарно; после сбоя могут остаться созданные каталоги, готовые файлы и частично записанный текущий файл. Автоматического отката нет.
- Защита от враждебной одновременной замены объектов файловой системы не гарантируется. Пакет не блокирует источник или каталог назначения от параллельных изменений.
- Права доступа, владелец и временные метки архива не восстанавливаются.
- Поддерживаются только реализованные возможности форматов и методы сжатия; принятие любого архива ZIP или TAR не гарантируется.

## Практическое использование

Выбирайте лимиты `ArchivePolicy` по ожидаемым архивам и доступным ресурсам. Перед извлечением подготовьте отдельный пустой каталог и учитывайте возможность частичного результата при ошибке выполнения. Различайте структурированные нарушения, ошибки открытия и ошибки извлечения.
