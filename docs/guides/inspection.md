# Проверка архива

Это руководство объясняет, как проверить архив до распаковки, как прочитать результат
и чем обычное нарушение заданных ограничений отличается от ошибки самого файла.

[`ArchiveGuard::inspect()`](../../src/ArchiveGuard.php) ничего не извлекает на диск.
Метод анализирует архив и возвращает [`InspectionResult`](../../src/InspectionResult.php).

## Базовый сценарий

```php
<?php

use Yaleksandr\ArchiveGuard\ArchiveGuard;
use Yaleksandr\ArchiveGuard\ArchivePolicy;
use Yaleksandr\ArchiveGuard\Exception\ArchiveOpenException;

$archivePath = '/path/to/archive.zip';

// Подберите ограничения под реальные архивы и ресурсы приложения.
$policy = new ArchivePolicy(
    maxArchiveBytes: 50_000_000,
    maxEntries: 1_000,
    maxEntryUncompressedBytes: 10_000_000,
    maxTotalUncompressedBytes: 100_000_000,
);

try {
    $result = new ArchiveGuard()->inspect($archivePath, $policy);

    if ($result->isAccepted()) {
        echo 'Архив прошёл проверку.' . PHP_EOL;
    } else {
        foreach ($result->violations() as $violation) {
            // code показывает причину отклонения, message — её текстовое описание.
            echo $violation->code->value . ': ' . $violation->message . PHP_EOL;
        }
    }
} catch (ArchiveOpenException $e) {
    echo 'Архив не удалось прочитать: ' . $e->getMessage() . PHP_EOL;
}
```

## ZIP с паролем

Для зашифрованного ZIP передайте пароль именованным аргументом:

```php
$result = new ArchiveGuard()->inspect(
    $archivePath,
    $policy,
    password: $password,
);
```

Семантика значения важна:

- `null` означает, что пароль не передан;
- `''` означает явно переданную пустую строку и не преобразуется в `null`;
- любое переданное значение, включая `''`, передаётся `ZipArchive` как пароль.

Пароль можно передать и для обычного незашифрованного ZIP: это само по себе не делает архив
недопустимым. TAR и TAR.GZ сами по себе не предусматривают встроенного парольного шифрования,
поэтому параметр `password` к этим форматам не применяется. Передача значения, отличного от
`null`, вызывает `InvalidArgumentException` с сообщением
`Password is only valid for ZIP archives.`

Для зашифрованных записей возможны разные причины отклонения:

- `encrypted_entry` — зашифрованная запись обнаружена, но пароль не передан;
- `unsupported_encryption` — пароль передан, но текущая среда выполнения не поддерживает
  используемый метод шифрования;
- `decryption_failed` — зашифрованное содержимое не удалось расшифровать или прочитать.
  Этот код не утверждает, что причина обязательно только в опечатке в пароле.

Пароль помечен как чувствительный параметр и не должен попадать в сообщения исключений,
нарушений или другую диагностику.

## Ограничения проверки

[`ArchivePolicy`](../../src/ArchivePolicy.php) задаёт не точные ожидаемые значения,
а **максимально допустимые пределы**:

- `maxArchiveBytes` — максимальный размер самого файла архива;
- `maxEntries` — максимальное количество файлов и папок внутри архива; для TAR в этот
  же предел входят некоторые служебные элементы формата;
- `maxEntryUncompressedBytes` — максимальный размер одного файла после распаковки;
- `maxTotalUncompressedBytes` — максимальный общий объём распакованных данных;
- `maxCompressionRatio` — необязательный дополнительный предел отношения распакованного
  размера к сжатому.

Например, если `maxArchiveBytes` равен `50_000_000`, файл размером 20 МБ не обязан иметь
какой-то точный размер: он просто не должен превышать заданный предел.

Проверка размера исходного архива выполняется до проверки допустимости пароля для формата,
поэтому `archive_too_large` имеет приоритет перед ошибкой передачи пароля для TAR/TAR.GZ.

Подробные правила для каждого параметра собраны в
[справочнике `ArchivePolicy`](../reference/policy-and-errors.md).

## Результат проверки

[`InspectionResult`](../../src/InspectionResult.php) предоставляет три основных метода:

- `format()` — определённый формат: `zip`, `tar` или `tar.gz`;
- `isAccepted()` — прошёл ли архив все проверки;
- `violations()` — список причин, по которым архив был отклонён.

Если `isAccepted()` вернул `false`, сам архив при этом может оставаться корректным как
контейнер. Например, он может содержать слишком большой файл, символическую ссылку или
зашифрованную ZIP-запись без переданного пароля.

Каждый [`Violation`](../../src/Violation.php) содержит:

- `code` — стабильный код причины, на который удобно опираться в логике приложения;
- `message` — диагностическое описание;
- `entryName` — имя файла, каталога или другого элемента архива, если нарушение связано с ним.

Полный список кодов приведён в [справочнике нарушений](../reference/policy-and-errors.md).

## Ошибки открытия и структуры

[`ArchiveOpenException`](../../src/Exception/ArchiveOpenException.php) возникает не потому,
что архив нарушил выбранную политику, а когда источник нельзя надёжно открыть или разобрать
либо принятое незашифрованное ZIP-содержимое нельзя прочитать.

Основные случаи:

- файл не существует, не является обычным локальным файлом или недоступен для чтения;
- переданный путь содержит `://`;
- содержимое не удаётся распознать как ZIP, TAR или TAR.GZ;
- ZIP, TAR или GZIP повреждён или имеет некорректную структуру;
- ZIP прошёл проверки метаданных, но содержимое принятой незашифрованной обычной записи нельзя корректно
  дочитать через `ZipArchive`.

Если зашифрованное содержимое при переданном пароле не удаётся расшифровать или прочитать,
`inspect()` возвращает отклонённый `InspectionResult` с нарушением `decryption_failed`, а не
`ArchiveOpenException`.

В перечисленных выше случаях `InspectionResult` не возвращается.

## Что именно проверяется

### Пути

Библиотека приводит обратные слеши к `/`, убирает пустые сегменты и `.` и отклоняет:

- `..`, позволяющий выйти в родительский каталог;
- абсолютные пути;
- пути с буквой диска;
- UNC-пути;
- имена с нулевым байтом;
- совпадения и конфликты путей после нормализации.

На Windows в том же общем процессе проверки применяются детерминированные ограничения
имён: недопустимый UTF-8, запрещённые Win32-символы, управляющие символы, завершающие
точки/пробелы, зарезервированные имена устройств и ASCII-регистронезависимые коллизии.

Детерминированные правила имён проверяются уже в `inspect()`, а условия, зависящие от
конкретного каталога назначения и его файловой системы, проверяются в `extract()`.

### Типы содержимого

Обычные файлы и каталоги разрешены. Символические ссылки, жёсткие ссылки TAR,
специальные объекты и неподдерживаемые возможности формата возвращаются как нарушения.

### Ограничения ресурсов

Проверяются:

- размер файла архива;
- количество файлов, папок и учитываемых служебных элементов формата;
- размер одного файла после распаковки;
- суммарный объём распакованных данных;
- при необходимости — отношение сжатого размера к распакованному.

### Содержимое ZIP

После проверки метаданных принятые обычные ZIP-файлы читаются потоково до EOF.
Проверка читает запись потоково и сверяет фактическое количество распакованных байтов
с принятыми метаданными.

Это означает, что `inspect()` проверяет не только метаданные центрального каталога ZIP. Если данные
записи повреждены и не читаются, архив не считается успешно проверенным только потому,
что метаданные выглядели корректно.

### Связь `inspect()` и `extract()`

Для свойств самого архива оба метода используют одинаковые входы:

```text
archivePath
ArchivePolicy
password
```

При одинаковых архиве, `ArchivePolicy` и `password` применяется одна семантика проверки архива.
Когда `extract()` доходит до проверки архива и эта проверка отклоняет его, метод выбрасывает
`ArchiveRejectedException` с соответствующим `InspectionResult` до публикации Atomic или
применения Merge.

Ошибки рабочего пространства, каталога назначения или блокировки могут возникнуть раньше.
`destinationPath` и `ExtractionOptions` задают способ применения результата к файловой системе
и не меняют семантику принятия самого архива. Права, конфликты Merge, состояние блокировки,
системные псевдонимы и изменения файловой системы во время выполнения проверяются только
в `extract()`.

### Особенности TAR и TAR.GZ

TAR и TAR.GZ поддерживают только реализованный набор обычных заголовков и расширений
GNU/PAX. Подробности приведены в
[справочнике поддерживаемых архивов](../reference/supported-archives.md).
