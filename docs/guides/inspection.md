# Проверка архива

Это руководство объясняет, как проверить архив до распаковки, как прочитать результат
и чем обычное нарушение заданных ограничений отличается от ошибки самого файла.

[`ArchiveGuard::inspect()`](../../src/ArchiveGuard.php) ничего не извлекает на диск.
Метод только анализирует архив и возвращает [`InspectionResult`](../../src/InspectionResult.php).

## Базовый сценарий

```php
<?php

use Yaleksandr\ArchiveGuard\ArchiveGuard;
use Yaleksandr\ArchiveGuard\ArchivePolicy;
use Yaleksandr\ArchiveGuard\Exception\ArchiveOpenException;

$archivePath = '/path/to/archive.zip';

// Значения ниже приведены только как пример.
$policy = new ArchivePolicy(
    maxArchiveBytes: 50_000_000,
    maxEntries: 1_000,
    maxEntryUncompressedBytes: 10_000_000,
    maxTotalUncompressedBytes: 100_000_000,
);

try {
    $result = new ArchiveGuard()->inspect($archivePath, $policy);

    if ($result->isAccepted()) {
        echo 'Архив прошёл проверку.' . PHP_EOL;
    } else {
        foreach ($result->violations() as $violation) {
            // code удобно использовать в логике приложения, message — для диагностики.
            echo $violation->code->value . ': ' . $violation->message . PHP_EOL;
        }
    }
} catch (ArchiveOpenException $e) {
    echo 'Архив не удалось прочитать: ' . $e->getMessage() . PHP_EOL;
}
```

## Ограничения проверки

[`ArchivePolicy`](../../src/ArchivePolicy.php) задаёт не точные ожидаемые значения,
а **максимально допустимые пределы**:

- `maxArchiveBytes` — максимальный размер самого файла архива;
- `maxEntries` — максимальное количество записей внутри архива: файлов, каталогов и,
  для некоторых TAR-архивов, служебных записей формата;
- `maxEntryUncompressedBytes` — максимальный размер одного файла после распаковки;
- `maxTotalUncompressedBytes` — максимальный общий объём распакованных данных;
- `maxCompressionRatio` — необязательный дополнительный предел отношения распакованного
  размера к сжатому.

Например, если `maxArchiveBytes` равен `50_000_000`, файл размером 20 МБ не обязан иметь
какой-то точный размер — он просто не должен превышать заданный предел.

Подробные правила для каждого параметра собраны в
[справочнике `ArchivePolicy`](../reference/policy-and-errors.md).

## Результат проверки

[`InspectionResult`](../../src/InspectionResult.php) предоставляет три основных метода:

- `format()` — определённый формат: `zip`, `tar` или `tar.gz`;
- `isAccepted()` — прошёл ли архив все проверки;
- `violations()` — список причин, по которым архив был отклонён.

Если `isAccepted()` вернул `false`, сам архив при этом мог быть корректным. Например,
он может содержать слишком большой файл или символическую ссылку, которую политика пакета
не разрешает извлекать.

Каждый [`Violation`](../../src/Violation.php) содержит:

- `code` — стабильный код причины, на который удобно опираться в логике приложения;
- `message` — диагностическое описание;
- `entryName` — имя записи внутри архива, если нарушение связано с конкретной записью.

Полный список кодов приведён в [справочнике нарушений](../reference/policy-and-errors.md).

## Ошибки открытия и структуры

[`ArchiveOpenException`](../../src/Exception/ArchiveOpenException.php) возникает не потому,
что архив не прошёл выбранную политику, а когда его нельзя корректно прочитать.

Основные случаи:

- файл не существует, не является обычным локальным файлом или недоступен для чтения;
- переданный путь содержит `://`;
- содержимое не похоже на ZIP, TAR или TAR.GZ;
- ZIP, TAR или GZIP повреждён или имеет некорректную структуру.

В этих случаях `InspectionResult` не возвращается.

## Что именно проверяется

### Пути

Archive Guard приводит обратные слеши к `/`, убирает пустые сегменты и `.` и отклоняет:

- `..`, позволяющий выйти в родительский каталог;
- абсолютные пути;
- пути с буквой диска;
- UNC-пути;
- имена с нулевым байтом;
- совпадения и конфликты путей после нормализации.

### Типы записей

Пакет разрешает обычные файлы и каталоги. Символические ссылки, жёсткие ссылки TAR,
специальные объекты и неподдерживаемые возможности формата возвращаются как нарушения.

### Ограничения ресурсов

Проверяются:

- размер файла архива;
- количество записей;
- размер одного файла после распаковки;
- суммарный объём распакованных данных;
- при необходимости — отношение сжатого размера к распакованному.

### Особенности ZIP, TAR и TAR.GZ

Для ZIP дополнительно проверяются шифрование и метод сжатия.

Если ZIP содержит зашифрованную запись, `inspect()` возвращает нарушение
`encrypted_entry`, а `isAccepted()` будет `false`. Текущая версия пакета не запрашивает
пароль и не извлекает зашифрованные записи.

TAR и TAR.GZ поддерживают только реализованный набор обычных заголовков и расширений
GNU/PAX. Подробности приведены в
[справочнике поддерживаемых архивов](../reference/supported-archives.md).
