# Проверка архива

`ArchiveGuard::inspect()` проверяет архив по переданной политике до извлечения и возвращает `InspectionResult` либо сообщает об ошибке открытия или структуры источника.

## Базовый сценарий

```php
<?php

use Yaleksandr\ArchiveGuard\ArchiveGuard;
use Yaleksandr\ArchiveGuard\ArchivePolicy;
use Yaleksandr\ArchiveGuard\Exception\ArchiveOpenException;

$archivePath = '/path/to/archive.zip';

$policy = new ArchivePolicy(50_000_000, 1_000, 10_000_000, 100_000_000);
$guard = new ArchiveGuard();

try {
    $result = $guard->inspect($archivePath, $policy);
    if ($result->isAccepted()) {
        echo 'Формат: ' . $result->format()->value . PHP_EOL;
    } else {
        foreach ($result->violations() as $violation) {
            echo $violation->code->value . ': ' . $violation->message;
            if ($violation->entryName !== null) {
                echo ' (' . $violation->entryName . ')';
            }
            echo PHP_EOL;
        }
    }
} catch (ArchiveOpenException $e) {
    echo 'Не удалось открыть или разобрать архив: ' . $e->getMessage() . PHP_EOL;
}
```

Числа здесь служат примером. Выбирайте лимиты под ожидаемые архивы и ресурсы приложения.

## Политика проверки

Четыре обязательных лимита ограничивают размер исходного файла, число записей, размер одной записи после распаковки и общий размер данных после распаковки. Необязательный `maxCompressionRatio` включает проверку отношения сжатия. См. [параметры политики](../reference/policy-and-errors.md).

## Результат проверки

`format()` возвращает `ArchiveFormat` (`zip`, `tar` или `tar.gz`). `isAccepted()` истинно, когда список `violations()` пуст. Принятый результат относится к этому вызову проверки и не заменяет проверку внутри `extract()`.

## Нарушение политики

Для опасной записи, неподдерживаемой возможности или превышенного лимита `inspect()` возвращает результат с одним или несколькими `Violation`. У каждого нарушения есть `code`, `message` и `entryName`; имя записи может быть `null`, например при превышении размера всего архива. Для логики приложения ориентируйтесь прежде всего на `code`; `message` предназначен для диагностического описания. Полный список кодов приведён в [справочнике](../reference/policy-and-errors.md).

## Ошибки открытия и структуры

Источник должен быть читаемым обычным локальным файлом; путь, содержащий `://`, не принимается. Нераспознанный формат, недоступный файл или структурно повреждённый архив приводят к `ArchiveOpenException`, а не к результату с `isAccepted() === false`.

## Что именно проверяется

- Пути: обратные слеши приводятся к `/`; пустые сегменты и `.` удаляются. Отклоняются `..`, абсолютные пути, пути с буквой диска, пути вида UNC и имена с нулевым байтом. Проверяются совпадения после нормализации и конфликты файла с каталогом или префиксом другого пути.
- Типы записей: символические ссылки, жёсткие ссылки TAR и специальные объекты отклоняются. Неподдерживаемые возможности формата также дают нарушение.
- Ресурсы: проверяются размер файла архива, число записей, размеры одной и всех распакованных записей; отношение сжатия проверяется только при заданном пороге.
- Особенности формата: ZIP проверяется на шифрование и поддержку метода сжатия; TAR и TAR.GZ допускают только реализованную семантику расширений GNU/PAX.
