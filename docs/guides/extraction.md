# Управляемое извлечение

Это руководство описывает два явных режима извлечения: Atomic для публикации нового
каталога целиком и Merge для применения архива к уже существующему каталогу.

[`ArchiveGuard::extract()`](../../src/ArchiveGuard.php) не использует более ранний результат
`inspect()` как разрешение на применение. Текущий архив проверяется заново в ходе операции,
а режим задаётся через [`ExtractionOptions`](../../src/ExtractionOptions.php).

## Перед извлечением

Подготовьте:

- читаемый локальный файл ZIP, TAR или TAR.GZ;
- [`ArchivePolicy`](../../src/ArchivePolicy.php) с подходящими для приложения пределами;
- [`ExtractionOptions`](../../src/ExtractionOptions.php), явно выбирающий Atomic или Merge;
- каталог назначения, соответствующий выбранному режиму.

Для `ExtractionOptions::atomic()` финальный каталог назначения **не должен существовать**.
Библиотека автоматически создаёт временный каталог в родительском каталоге назначения;
создавать его вручную не нужно. Родитель каталога назначения должен позволять создать
этот временный каталог и служебный каталог кооперативных блокировок.

Для `ExtractionOptions::merge(...)` каталог назначения, наоборот, должен существовать и быть
читаемым реальным каталогом, а не ссылкой. Архив полностью подготавливается в автоматически
созданном временном каталоге в родительском каталоге назначения, после чего результат
применяется к каталогу назначения.

## Базовый сценарий: Atomic

```php
<?php

use Yaleksandr\ArchiveGuard\ArchiveGuard;
use Yaleksandr\ArchiveGuard\ArchivePolicy;
use Yaleksandr\ArchiveGuard\Exception\ArchiveOpenException;
use Yaleksandr\ArchiveGuard\Exception\ArchiveRejectedException;
use Yaleksandr\ArchiveGuard\Exception\ExtractionException;
use Yaleksandr\ArchiveGuard\ExtractionOptions;

$archivePath = '/path/to/archive.zip';
$destinationPath = '/path/to/result';

// Подберите ограничения под реальные архивы и ресурсы приложения.
$policy = new ArchivePolicy(
    maxArchiveBytes: 50_000_000,
    maxEntries: 1_000,
    maxEntryUncompressedBytes: 10_000_000,
    maxTotalUncompressedBytes: 100_000_000,
);

try {
    $result = new ArchiveGuard()->extract(
        $archivePath,
        $destinationPath,
        $policy,
        ExtractionOptions::atomic(),
    );

    echo 'Файлов применено: ' . $result->filesExtracted() . PHP_EOL;
    echo 'Каталогов создано: ' . $result->directoriesCreated() . PHP_EOL;
    echo 'Записано байт: ' . $result->bytesWritten() . PHP_EOL;
} catch (ArchiveRejectedException $e) {
    foreach ($e->inspectionResult()->violations() as $violation) {
        echo $violation->code->value . PHP_EOL;
    }
} catch (ArchiveOpenException | ExtractionException $e) {
    echo $e->getMessage() . PHP_EOL;
}
```

Atomic использует автоматически созданный временный каталог в родительском каталоге назначения.
После полного извлечения и проверок он переименовывается в отсутствующий финальный каталог
назначения через `rename()`.

## Merge и стратегии конфликтов

Для применения архива к существующему каталогу используйте `ExtractionOptions::merge()`:

```php
<?php

use Yaleksandr\ArchiveGuard\ArchiveGuard;
use Yaleksandr\ArchiveGuard\ArchivePolicy;
use Yaleksandr\ArchiveGuard\ExtractionConflictStrategy;
use Yaleksandr\ArchiveGuard\ExtractionOptions;

$policy = new ArchivePolicy(
    maxArchiveBytes: 50_000_000,
    maxEntries: 1_000,
    maxEntryUncompressedBytes: 10_000_000,
    maxTotalUncompressedBytes: 100_000_000,
);

$result = new ArchiveGuard()->extract(
    '/path/to/archive.zip',
    '/path/to/existing-directory',
    $policy,
    ExtractionOptions::merge(ExtractionConflictStrategy::Reject),
);
```

Доступны три стратегии для конфликта файла из архива с уже существующим обычным файлом:

- `Reject` — ошибка на предварительной проверке до начала применения Merge;
- `Skip` — существующий файл сохраняется, файл из временного каталога не применяется;
- `Overwrite` — существующий обычный файл заменяется обычным файлом из временного каталога.

Для каталогов правило другое: если и в архиве, и в каталоге назначения по одному пути находятся
каталоги, существующий каталог переиспользуется. Конфликт файла и каталога в любом направлении
всегда является ошибкой. Символические ссылки и специальные объекты на затронутом пути назначения
также отклоняются.

`Overwrite` относится только к замене обычного файла другим обычным файлом. Он не превращает
Merge в разрешение заменять каталоги, ссылки или другие типы объектов.

## Что происходит до применения

`extract()` не использует более ранний результат `inspect()` как разрешение на запись.
Архив проверяется заново с текущими `archivePath`, `ArchivePolicy` и `password`.

Общая последовательность:

1. Проверяется источник и определяется формат по содержимому.
2. Проверяется `maxArchiveBytes`.
3. Проверяется допустимость пароля для формата.
4. Для каталога назначения берётся кооперативная блокировка Archive Guard.
5. Библиотека создаёт временный каталог в родительском каталоге назначения.
6. Архив полностью извлекается и проверяется внутри него.
7. Для Atomic временный каталог публикуется целиком в отсутствующий каталог назначения.
8. Для Merge выполняется полная предварительная проверка, затем файлы применяются согласно
   выбранной стратегии конфликтов.
9. Временный каталог очищается, блокировка освобождается.

Для ZIP содержимое читается через общий потоковый механизм: фактический объём проверяется
во время чтения, а целая запись не загружается в память.

Для TAR и TAR.GZ архив читается отдельным проходом извлечения. Порядок, путь, тип и размер
каждого элемента сверяются с результатом проверки; если источник изменился между проходами,
извлечение прекращается.

## Пароль ZIP

Пароль передаётся отдельным именованным аргументом:

```php
$result = new ArchiveGuard()->extract(
    $archivePath,
    $destinationPath,
    $policy,
    ExtractionOptions::atomic(),
    password: $password,
);
```

`null` означает отсутствие пароля. Пустая строка `''` считается переданным паролем и не
нормализуется в `null`.

Для обычного ZIP переданный пароль допустим. Для зашифрованного ZIP без пароля возвращается
`encrypted_entry`; неподдерживаемый текущей средой метод шифрования даёт `unsupported_encryption`;
если зашифрованное содержимое не удалось расшифровать или прочитать, используется
`decryption_failed`.

`decryption_failed` не означает, что причина гарантированно только в неверном пароле:
ошибка может быть обнаружена средой выполнения при чтении зашифрованного или сжатого содержимого.

TAR и TAR.GZ сами по себе не предусматривают встроенного парольного шифрования, поэтому
параметр `password` к этим форматам не применяется. Если передать значение, отличное от `null`,
метод выбросит `InvalidArgumentException`.

Пароль ZIP помечен как чувствительный параметр и не сохраняется в `ExtractionOptions`,
`ExtractionResult`, рабочем пространстве или диагностических сообщениях.

## Результат

[`ExtractionResult`](../../src/ExtractionResult.php) показывает фактически применённые
изменения:

- `format()` — формат архива;
- `filesExtracted()` — количество новых и перезаписанных файлов, реально применённых к каталогу назначения;
- `directoriesCreated()` — количество реально созданных каталогов;
- `bytesWritten()` — количество байтов содержимого новых и перезаписанных файлов;
- `filesSkipped()` — количество файлов, реально пропущенных стратегией `Skip`;
- `filesOverwritten()` — количество существовавших файлов, реально заменённых `Overwrite`.

Для Atomic `filesSkipped()` и `filesOverwritten()` всегда равны нулю.

## Ошибки

Во время `extract()` возможны три основные группы ошибок:

- [`ArchiveOpenException`](../../src/Exception/ArchiveOpenException.php) — исходный файл
  нельзя открыть или корректно разобрать либо принятое незашифрованное ZIP-содержимое нельзя
  надёжно прочитать;
- [`ArchiveRejectedException`](../../src/Exception/ArchiveRejectedException.php) — архив
  прочитан, но не прошёл проверки самого архива; `inspectionResult()` содержит причины;
- [`ExtractionException`](../../src/Exception/ExtractionException.php) — проблема связана
  с каталогом назначения, кооперативной блокировкой, временным каталогом, предварительной
  проверкой или применением Merge либо операциями ввода-вывода файловой системы.

`InvalidArgumentException` отдельно используется, когда пароль передан для TAR/TAR.GZ.

Коды нарушений внутри `ArchiveRejectedException` перечислены в
[справочнике ошибок](../reference/policy-and-errors.md).

## Как применяются Atomic и Merge

### Atomic

Atomic полностью подготавливает результат в автоматически созданном временном каталоге в
родительском каталоге назначения. После успешных проверок временный каталог переименовывается
в новый финальный каталог назначения через `rename()`. Если публикация не выполняется,
библиотека удаляет временный каталог при завершении операции.

### Merge

Merge предназначен для существующего каталога назначения. До его изменения пакет полностью
подготавливает архив во временном каталоге и выполняет предварительную проверку конфликтов.
После успешной проверки изменения применяются последовательно согласно выбранной стратегии
`Reject`, `Skip` или `Overwrite`.

Если файловая система возвращает ошибку уже во время применения, `ExtractionException`
останавливает дальнейшие операции, а ранее успешно применённые изменения остаются в каталоге.
Такое поведение относится именно к фазе применения Merge и не затрагивает предварительную
проверку архива и конфликтов.

### Кооперативная блокировка

Оба режима используют `.archive-guard-locks` для координации параллельных операций Archive Guard,
работающих с одним каталогом назначения. Блокировка создаётся и используется библиотекой
автоматически.

## Права доступа Merge

Нельзя свести требования Merge к правилу «весь каталог назначения должен быть доступен для записи».

- Для `Skip`, если изменение конфликтующего файла не требуется, права на запись только ради
  этого файла не нужны.
- Для создания нового файла или каталога и для `Overwrite` родитель конкретного изменяемого
  объекта должен быть доступен для записи.
- На Windows перезаписываемый файл дополнительно должен быть доступен для записи.
- На POSIX файл только для чтения можно заменить, если его родительский каталог доступен для записи.
- Корневой каталог Merge может быть только для чтения, если изменения не требуют записи прямо в него.

Родитель каталога назначения также используется библиотекой для автоматически создаваемого
временного каталога и пространства кооперативных блокировок.

## Windows

Детерминированные правила совместимости имён текущей платформы уже проверяются в общем
процессе проверки. На Windows отклоняются, например:

- недопустимый UTF-8 в компоненте пути;
- запрещённые Win32-символы и управляющие символы;
- имена с завершающей точкой или пробелом;
- зарезервированные устройства `CON`, `NUL`, `PRN`, `AUX`, `COM1...`, `LPT1...`;
- ASCII-регистронезависимые коллизии путей.

Проверки, которые зависят от конкретного каталога назначения и его файловой системы,
выполняются на этапе `extract()`.
