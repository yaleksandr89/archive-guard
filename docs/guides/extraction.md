# Управляемое извлечение

Это руководство описывает извлечение с учётом встроенных проверок: что нужно подготовить
заранее, какие ошибки возможны и что останется на диске, если запись прервётся.

[`ArchiveGuard::extract()`](../../src/ArchiveGuard.php) сначала проверяет архив по переданной
политике и только после успешной проверки начинает создавать файлы.

## Перед извлечением

Подготовьте:

- читаемый локальный файл ZIP, TAR или TAR.GZ;
- [`ArchivePolicy`](../../src/ArchivePolicy.php) с подходящими для приложения пределами;
- отдельный пустой каталог назначения.

Каталог назначения должен **существовать заранее и быть пустым**. Текущая версия не
распаковывает архив поверх уже существующих файлов.

Если приложение использует одну общую папку для всех распаковок, создавайте внутри неё
отдельный новый подкаталог для каждой операции. Так содержимое разных архивов не смешивается,
а библиотека может проверить каталог назначения целиком до начала записи.

PHP-процессу нужны права на создание файлов и подкаталогов внутри этого каталога.

## Базовый сценарий

```php
<?php

use Yaleksandr\ArchiveGuard\ArchiveGuard;
use Yaleksandr\ArchiveGuard\ArchivePolicy;
use Yaleksandr\ArchiveGuard\Exception\ArchiveOpenException;
use Yaleksandr\ArchiveGuard\Exception\ArchiveRejectedException;
use Yaleksandr\ArchiveGuard\Exception\ExtractionException;

$archivePath = '/path/to/archive.zip';
$destinationPath = '/path/to/empty-directory';

// Подберите ограничения под реальные архивы и ресурсы приложения.
$policy = new ArchivePolicy(
    maxArchiveBytes: 50_000_000,
    maxEntries: 1_000,
    maxEntryUncompressedBytes: 10_000_000,
    maxTotalUncompressedBytes: 100_000_000,
);

try {
    $result = new ArchiveGuard()->extract($archivePath, $destinationPath, $policy);

    echo 'Файлов: ' . $result->filesExtracted() . PHP_EOL;
    echo 'Каталогов: ' . $result->directoriesCreated() . PHP_EOL;
    echo 'Записано байт: ' . $result->bytesWritten() . PHP_EOL;
} catch (ArchiveRejectedException $e) {
    // Архив прочитан, но не прошёл заданные проверки.
    foreach ($e->inspectionResult()->violations() as $violation) {
        echo $violation->code->value . PHP_EOL;
    }
} catch (ArchiveOpenException $e) {
    // Исходный файл нельзя открыть или корректно разобрать.
    echo $e->getMessage() . PHP_EOL;
} catch (ExtractionException $e) {
    // Ошибка назначения или сбой уже во время извлечения.
    echo $e->getMessage() . PHP_EOL;
}
```

## Что происходит перед записью

`extract()` всегда проверяет текущее состояние архива непосредственно перед записью.
Эта проверка выполняется независимо от того, вызывался ли `inspect()` раньше.

Последовательность выглядит так:

1. Библиотека открывает и проверяет архив.
2. Если найдены нарушения, выбрасывается
   [`ArchiveRejectedException`](../../src/Exception/ArchiveRejectedException.php),
   а запись ещё не началась.
3. Проверяется каталог назначения.
4. Каждый файл создаётся только если по его пути ещё ничего нет; существующий объект не заменяется.
5. Во время записи фактический объём каждого файла и общий объём распакованных данных
   сверяются с заданными лимитами и размерами, полученными при проверке. Если архив
   начинает выдавать больше данных, чем было разрешено, извлечение прекращается.
6. TAR и TAR.GZ читаются дважды: сначала для проверки, затем для извлечения. Во время
   второго прохода порядок, путь, тип и размер каждого элемента сверяются с результатом
   первой проверки. Если архив изменился между проходами, извлечение прекращается.

## Результат

[`ExtractionResult`](../../src/ExtractionResult.php) показывает:

- `format()` — формат архива;
- `filesExtracted()` — сколько файлов создано;
- `directoriesCreated()` — сколько каталогов создано;
- `bytesWritten()` — сколько байтов записано в файлы.

## Ошибки

Во время `extract()` возможны три основные группы ошибок:

- [`ArchiveOpenException`](../../src/Exception/ArchiveOpenException.php) — исходный файл
  нельзя открыть или корректно разобрать;
- [`ArchiveRejectedException`](../../src/Exception/ArchiveRejectedException.php) — архив
  корректный, но не прошёл ограничения или проверки;
- [`ExtractionException`](../../src/Exception/ExtractionException.php) — проблема с
  каталогом назначения, именем целевого файла или самой записью на диск.

Коды нарушений внутри `ArchiveRejectedException` перечислены в
[справочнике ошибок](../reference/policy-and-errors.md).

## Частичный сбой и атомарность

Сейчас данные записываются непосредственно в заранее подготовленный каталог.
Это позволяет проверять фактически записанный объём и не перезаписывать существующие файлы,
но означает, что операция **не является атомарной**.

Если после создания нескольких файлов закончится место на диске, процесс потеряет права
на запись или произойдёт другая ошибка ввода-вывода, уже созданные файлы и каталоги останутся.
Текущий файл тоже может остаться записанным частично.

Полностью атомарный вариант технически возможен, но это уже другой контракт: потребовался бы
временный каталог, завершение всей распаковки в нём и отдельный финальный перенос результата.
Такой перенос по-разному ведёт себя на разных файловых системах и в Windows, поэтому текущая
версия не делает вид, что обеспечивает атомарность там, где её нет.

Если приложение создаёт отдельный каталог специально для одной операции и полностью им
владеет, оно может удалить этот каталог после `ExtractionException` по своим правилам.

## Windows

Windows накладывает дополнительные ограничения на имена файлов, которых нет в общем формате
ZIP или TAR. Перед первой записью библиотека дополнительно отклоняет, например:

- имена устройств `CON`, `NUL`, `PRN` и подобные;
- запрещённые Windows символы;
- имена, заканчивающиеся точкой или пробелом;
- пути, которые различаются только ASCII-регистром и в Windows указывают на одно место.

Поэтому один и тот же архив может пройти `inspect()` на уровне формата, но быть отклонён
`extract()` именно при подготовке к записи в Windows.

## Метаданные файлов

Архив может хранить не только содержимое файла, но и его права доступа, владельца и время
изменения. Текущая версия извлекает содержимое файлов и структуру каталогов, но не применяет
эти метаданные из архива.

Дополнительные границы и рекомендации собраны в [модели безопасности](../security-model.md).
