# 安全模型

本页说明本包能防护哪些常见的归档文件处理问题、会执行哪些检查，以及应用仍需自行控制哪些风险。

这里描述的是库的行为，并不代表已经完成正式安全审计。

## 哪些归档数据被视为潜在危险

来自归档文件本身的数据都被视为潜在危险。会检查：

- 文件名和路径；
- 内容类型：普通文件、目录、链接或特殊对象；
- 声明的文件大小；
- 解压数据总量；
- 压缩相关信息；
- ZIP、TAR 和 TAR.GZ 的附加格式功能。

原因很简单：归档文件可以在结构上完全有效，但仍包含 `../file` 这样的路径、符号链接、
解压后极大的文件，或应用没有预期处理的格式功能。

## `inspect()` 会做什么

[`ArchiveGuard::inspect()`](../src/ArchiveGuard.php) 检查归档文件，但不会提取文件。

检查包括：

- 路径规范化和验证；
- 检测冲突路径；
- 检查每个元素的类型：文件、目录、链接或特殊对象；
- [`ArchivePolicy`](../src/ArchivePolicy.php) 中的限制；
- ZIP、TAR 和 TAR.GZ 特有的检查。

如果归档文件结构有效但违反某条规则，应用会收到包含原因的
[`InspectionResult`](../src/InspectionResult.php)。如果文件本身无法可靠读取或解析，
则抛出 `ArchiveOpenException`。

## `extract()` 在写入前会做什么

[`ArchiveGuard::extract()`](../src/ArchiveGuard.php) 总会在提取前检查归档文件的当前状态。
之前返回的 `InspectionResult` 不会被当作写入许可。

随后会：

1. 确认目标目录已经存在并且为空；
2. 检查目标目录本身不是符号链接；
3. 不覆盖已有文件；
4. 将每个文件的实际大小和解压总量与配置的限制以及检查阶段得到的大小比较。
   如果数据量超过允许范围，提取停止；
5. TAR 和 TAR.GZ 会为了提取再读取一次。每个元素的顺序、路径、类型和大小都会与第一次检查结果比较；
   如果两次之间归档文件发生变化，提取停止。

目标目录由应用创建，而不是由库创建。当前版本只在独立空目录中工作。
如果应用把提取结果保存在同一个公共目录下，应为每次操作新建一个空子目录。

## 资源限制

四个必填限制控制：

- 源归档文件大小；
- 文件、文件夹以及计入限制的格式元数据元素数量；
- 单个文件或其他元素解压后的大小；
- 解压数据总量。

可选的 `maxCompressionRatio` 为压缩数据过度膨胀增加额外检查：

- ZIP 使用元数据中的大小；
- TAR.GZ 使用解压器实际产生的数据量；
- 普通 TAR 不使用此限制。

这只是额外的启发式检查，不能替代主要大小限制。

## Windows 特点

有些名称在 ZIP 或 TAR 中是合法的，但无法在 Windows 上安全创建。

写入前还会额外拒绝例如：

- `CON`、`NUL`、`PRN` 等保留设备名称；
- Windows 不允许的字符；
- 以点或空格结尾的名称；
- 仅 ASCII 大小写不同、但 Windows 会认为是同一路径的路径。

因此，通用 `inspect()` 可能接受某个归档文件，而 Windows 上的 `extract()` 会在第一次写入前
以 `ExtractionException` 停止。

## 限制以及存在原因

### 提取不是原子操作

文件会直接写入准备好的目标目录。如果操作在成功写入几个文件后中断，
这些文件会保留在磁盘上。

完全原子的方案需要先把所有内容解压到临时目录，再通过一次最终操作替换或移动完整结果。
不同文件系统和 Windows 对这种移动有不同限制，而且这需要独立的公共契约。
因此当前版本不会声称提供原子性。

### 目录不会被锁定以阻止其他进程

当前版本不会对目标目录设置系统级锁。如果另一个进程同时修改目录内容，
库的检查不能保证防护这些变化。

提取时请使用只有当前应用可以访问的独立目录。

### 不会恢复归档文件中的权限和所有者

归档文件可以保存自己的权限、所有者和时间戳。当前版本会提取文件内容和目录结构，
但不会应用这些值。

### 并非所有 ZIP 或 TAR 功能都受支持

如果库无法足够可靠地理解某个格式功能，它会拒绝归档文件，而不是猜测应该如何处理。
例如，当前版本不会提取加密 ZIP 元素。

准确限制列表请参阅
[支持的归档格式](reference/supported-archives_zh.md)。

## 实践建议

- 根据应用实际处理的归档文件大小设置 `ArchivePolicy`；
- 每次提取使用独立的空子目录；
- 不要允许不受信任的进程同时修改该目录；
- 分别处理检查违规、打开错误和写入错误；
- 如果临时目录由应用自己创建并完全拥有，则提取失败后可以按照自己的规则删除它。
