# Политика, нарушения и ошибки

Этот справочник описывает параметры проверки, режимы извлечения, результаты, коды нарушений
и исключения, которые приложение может получить при работе с пакетом.

## ArchivePolicy

[`ArchivePolicy`](../../src/ArchivePolicy.php) передаётся в каждый вызов `inspect()` или
`extract()` и задаёт **максимально допустимые**, а не ожидаемые точные значения.

```php
<?php

use Yaleksandr\ArchiveGuard\ArchivePolicy;

$policy = new ArchivePolicy(
    maxArchiveBytes: 50_000_000,
    maxEntries: 1_000,
    maxEntryUncompressedBytes: 10_000_000,
    maxTotalUncompressedBytes: 100_000_000,
    maxCompressionRatio: 100.0,
);
```

| Параметр | Что ограничивает | Допустимое значение |
| --- | --- | --- |
| `maxArchiveBytes` | Максимальный размер самого файла архива | Целое число больше нуля |
| `maxEntries` | Максимальное количество файлов и папок внутри архива; для TAR в этот же предел входят некоторые служебные элементы формата | Целое число больше нуля |
| `maxEntryUncompressedBytes` | Максимальный размер одного файла или другого элемента после распаковки | Целое число больше нуля |
| `maxTotalUncompressedBytes` | Максимальный суммарный объём распакованных данных | Целое число больше нуля |
| `maxCompressionRatio` | Дополнительный предел отношения распакованного размера к сжатому | `null` или конечное число больше нуля |

У первых четырёх параметров нет значений по умолчанию: приложение должно выбрать их само.
`maxCompressionRatio` необязателен и по умолчанию равен `null`.

Проверка отношения сжатия работает по-разному:

- для ZIP используются размеры из метаданных элемента;
- для TAR.GZ учитывается фактический объём данных, который выдаёт GZIP-декомпрессор;
- для обычного TAR этот предел не применяется.

Неверные значения конструктора вызывают стандартный `InvalidArgumentException`.

## InspectionResult

[`InspectionResult`](../../src/InspectionResult.php) возвращается, когда источник удалось
открыть и проверить как поддерживаемый архив.

Доступные методы:

- `format()` — возвращает [`ArchiveFormat`](../../src/ArchiveFormat.php): `zip`, `tar`
  или `tar.gz`;
- `isAccepted()` — возвращает `true`, если нарушений нет;
- `violations()` — возвращает список объектов [`Violation`](../../src/Violation.php).

Если файл нельзя открыть, распознать или корректно разобрать либо содержимое принятой
незашифрованной ZIP-записи нельзя надёжно прочитать, возникает `ArchiveOpenException`.

## ExtractionOptions

[`ExtractionOptions`](../../src/ExtractionOptions.php) обязательно передаётся в `extract()`
и создаётся одним из двух именованных конструкторов:

```php
ExtractionOptions::atomic();

ExtractionOptions::merge(
    ExtractionConflictStrategy::Reject,
);
```

`atomic()` выбирает публикацию результата в новый каталог назначения, которого до операции
не существует.

`merge(...)` выбирает применение результата к существующему каталогу и требует одну из
стратегий [`ExtractionConflictStrategy`](../../src/ExtractionConflictStrategy.php):

- `Reject` — существующий обычный файл считается конфликтом до начала применения;
- `Skip` — существующий обычный файл сохраняется;
- `Overwrite` — существующий обычный файл заменяется обычным файлом из архива.

Существующий каталог переиспользуется, если архив тоже содержит каталог по этому пути.
Конфликты файла и каталога, ссылки и специальные объекты на затронутых путях отклоняются
независимо от стратегии.

## ExtractionResult

[`ExtractionResult`](../../src/ExtractionResult.php) описывает фактически применённые
изменения:

- `format()` — формат архива;
- `filesExtracted()` — новые и перезаписанные файлы, реально применённые к каталогу назначения;
- `directoriesCreated()` — реально созданные каталоги;
- `bytesWritten()` — количество байтов содержимого применённых новых и перезаписанных файлов;
- `filesSkipped()` — реально пропущенные файлы;
- `filesOverwritten()` — реально заменённые существующие файлы.

Для Atomic `filesSkipped()` и `filesOverwritten()` равны нулю.

## Violation

[`Violation`](../../src/Violation.php) содержит три публичных свойства:

- `code` — значение [`ViolationCode`](../../src/ViolationCode.php), предназначенное для
  программной обработки;
- `message` — короткое диагностическое описание;
- `entryName` — имя файла, каталога или другого элемента архива либо `null`, если
  нарушение относится ко всему архиву.

Для условий в коде лучше использовать `code`, а не сравнивать текст `message`.

## ViolationCode

| Значение | Что означает |
| --- | --- |
| `unsafe_path` | Путь записи может выйти за допустимую структуру каталога или содержит недопустимую форму |
| `path_collision` | Два пути после нормализации или платформенного сопоставления конфликтуют |
| `platform_incompatible_path` | Компонент пути несовместим с детерминированными правилами текущей платформы |
| `symlink_entry` | В архиве обнаружена символическая ссылка |
| `hardlink_entry` | В TAR обнаружена жёсткая ссылка |
| `special_entry` | Обнаружен специальный объект, например устройство |
| `archive_too_large` | Размер файла архива превышает `maxArchiveBytes` |
| `too_many_entries` | Количество файлов, папок и учитываемых служебных элементов превышает `maxEntries` |
| `entry_too_large` | Один файл или другой элемент после распаковки превышает `maxEntryUncompressedBytes` |
| `total_size_exceeded` | Общий объём распакованных данных превышает `maxTotalUncompressedBytes` |
| `compression_ratio_exceeded` | Превышен заданный предел отношения распакованного размера к сжатому |
| `encrypted_entry` | ZIP содержит зашифрованную запись, но пароль не передан |
| `unsupported_encryption` | Пароль передан, но текущая среда выполнения не поддерживает метод шифрования записи |
| `decryption_failed` | Зашифрованное содержимое не удалось расшифровать или прочитать |
| `unsupported_compression` | Метод сжатия ZIP не поддерживается средой для распаковки |
| `unsupported_feature` | Архив использует возможность формата, которую пакет не поддерживает |

`decryption_failed` означает ошибку расшифровки или чтения зашифрованного содержимого.
`ZipArchive`/`libzip` не всегда позволяет определить точную причину этой ошибки.

`entryName` есть не у каждого нарушения. Например, превышение размера всего архива относится
к архиву целиком, поэтому имя отдельного элемента там отсутствует.

## Исключения

Все исключения пакета наследуются от
[`ArchiveGuardException`](../../src/Exception/ArchiveGuardException.php), который, в свою
очередь, наследуется от `RuntimeException`.

- [`ArchiveOpenException`](../../src/Exception/ArchiveOpenException.php) — исходный файл
  нельзя открыть, формат не распознан, структура повреждена или принятое незашифрованное
  ZIP-содержимое нельзя надёжно прочитать. Ошибка расшифровки или чтения зашифрованного
  содержимого при переданном пароле возвращает `decryption_failed`; `extract()` передаёт
  это отклонение в `ArchiveRejectedException`.
- [`ArchiveRejectedException`](../../src/Exception/ArchiveRejectedException.php) —
  проверка архива отклонила его; публикация Atomic или применение Merge ещё не начались.
  Метод `inspectionResult()` возвращает причины отклонения. Файлы во временном каталоге могли быть
  созданы до того, как стало наблюдаемым полное отклонение архива.
- [`ExtractionException`](../../src/Exception/ExtractionException.php) — проблема относится
  к каталогу назначения, блокировке, временному каталогу, предварительной проверке или
  применению Merge, публикации Atomic либо операциям ввода-вывода файловой системы.

`InvalidArgumentException` не наследует `ArchiveGuardException`. Он используется для неверных
значений `ArchivePolicy`. Параметр `password` относится к ZIP; TAR и TAR.GZ сами по себе не
предусматривают встроенного парольного шифрования, поэтому передача для них значения, отличного
от `null`, также приводит к `InvalidArgumentException`.

## Как различать результат и исключение

### `inspect()`

- Если архив прошёл проверки, возвращается `InspectionResult` с `isAccepted() === true`.
- Если архив удалось проверить, но найдены нарушения, возвращается `InspectionResult`
  с `isAccepted() === false`.
- Если источник нельзя открыть или корректно разобрать либо принятое незашифрованное
  ZIP-содержимое нельзя надёжно прочитать, возникает `ArchiveOpenException`.
- Для ZIP можно передать `password`; TAR и TAR.GZ не предусматривают встроенного парольного
  шифрования, поэтому `password`, отличный от `null`, для них приводит к `InvalidArgumentException`.

### `extract()`

`extract()` принимает:

```text
archivePath
destinationPath
ArchivePolicy
ExtractionOptions
password = null
```

Входные данные проверки архива `archivePath`, `ArchivePolicy` и `password` проверяются по той
же семантике, что и в `inspect()`.

- Если проверка архива отклонила его, `extract()` выбрасывает `ArchiveRejectedException` до
  публикации Atomic или применения Merge; полная проверка может происходить уже после
  создания временного каталога в родительском каталоге назначения. `inspectionResult()`
  содержит причины отклонения.
- Ошибка открытия или структуры либо чтения принятого незашифрованного ZIP-содержимого
  приводит к `ArchiveOpenException`.
- Проблема каталога назначения, конфликт применения или ошибка файловой системы во время
  выполнения приводит к `ExtractionException`.
- При успешном завершении возвращается `ExtractionResult`.

Для `maxArchiveBytes` сохраняется приоритет ограничения размера исходного архива: слишком большой архив
отклоняется раньше, чем проверяется допустимость пароля для TAR/TAR.GZ.

Практические примеры есть в руководствах по
[`inspect()`](../guides/inspection.md) и [`extract()`](../guides/extraction.md).
